# Week 10 Day 4：校园支持业务闭环验收与范围冻结

日期：2026-09-28

## 已验证的真实 Smoke

### 1. 学生到支持人员的工单闭环

在本机 Java 服务、学生虚拟机 PostgreSQL 和 RabbitMQ 环境中完成：

```text
学生创建 OPEN 工单
→ Support 从工作队列领取
→ OPEN → IN_PROGRESS → RESOLVED
→ Outbox Scheduler 投递 RabbitMQ
→ Inbox 幂等记录
→ 学生通知列表出现三条进度通知
→ 学生标记一条通知为已读
```

本次 Smoke 的最终观测值：`created=OPEN`、`resolved=RESOLVED`、
`notifications=3`、`readAt` 为非空时间。

### 2. Agent 辅助与人工交接

在本机 Agent 服务和 Java 服务运行时完成：

```text
校园知识咨询 → answer_support_knowledge → answered + 1 citation
查询本人刚创建的工单 → lookup_ticket → 返回相同 ticketId
“密码泄露” → handoff_to_human → create_human_handoff_task
```

最后一条在 Java `human_handoff_task` 中创建了 `PENDING` 任务；Trace 节点为：

```text
triage → route_after_triage → handoff_to_human → create_human_handoff_task
```

## 环境注意事项

开发机存在指向 `127.0.0.1:9` 的无效 HTTP(S) 代理变量。Agent 进程若继承该变量，
外部 Embedding 请求会得到 `embedding-model-network-error`；当前 Smoke 使用未继承该
失效代理的 Agent 进程完成。该事项属于本机运行环境，不应误判为知识库没有证据。

## 范围冻结：可以陈述的能力

- 学生可创建、分页查看自己的工单；Support/Admin 可查看队列、领取并更新状态。
- 状态与领取事件写入 Outbox，经 RabbitMQ、Inbox 幂等处理后生成学生通知。
- Agent 可在受控路由下查询本人工单、回答有引用的校园知识，或将高风险请求创建为
  可领取的人工交接任务。
- 已有真实 PostgreSQL、RabbitMQ、Agent→Java HTTP 以及模型/Embedding Smoke 的选中证据。

## 未验证边界：不得夸大

- 未做多 Java 实例、多 Consumer、多 Worker 协调或高并发压测。
- 未验证 RabbitMQ Broker 故障恢复、网络分区和长期重投的生产行为。
- 未证明模型在大量真实校园问题上的正确率、延迟、费用或并发吞吐。
- Agent 图没有持久化 Checkpoint，也不是自由协商式 Multi-Agent。
- 未运行并通过全量 Maven 回归；选中的 Smoke 不能替代全量回归。
