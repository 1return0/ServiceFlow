# EduOps P0范围

## 业务范围

P0只处理合成的校园IT与教学服务场景：校园账号或学习平台访问、校园网或VPN故障、实验室软件与权限申请、教室设备报修、打印或校园卡异常申诉，以及人工升级。

选择校园服务工单是因为学生容易理解和接触这类流程，同时服务规则、工单状态、SLA计算、权限申请和风险升级能形成完整工具链；这不代表系统与任何真实学校平台连接。

## P0功能

1. 结构化合成服务请求、服务规则和客服对话；
2. 确定性规则流程；
3. 单Agent工具调用基线；
4. 固定Workflow；
5. Multi-Agent与Critic；
6. 服务请求、规则、优先级与SLA计算、工单状态保存和人工升级工具；
7. Checkpoint、超时、重试、预算与循环限制；
8. 非法JSON、工具超时、冲突规则、缺失服务请求和重复调用故障注入；
9. 意图、规则、金额、解决方案、风险升级和工具调用评测；
10. 全链路Trace、延迟、Token和成本报告。

## P0非目标

- 连接学校真实账号、教务、宿管、校园卡或设备平台；
- 修改真实账号、课程、设备、校园卡或消息状态；
- 冒充人工服务人员作出承诺；
- 使用真实用户对话或个人信息；
- 自动处理安全、隐私、投诉、权限授予或规则冲突案例；
- 用Agent替代确定性SLA计算、权限判断和服务请求状态查询。

## 最终验收

- 至少200条合成客服案例，其中严重风险案例不少于40条；
- 规则、单Agent、固定Workflow和Multi-Agent四组实验；
- 意图识别F1、规则适用准确率、金额准确率和严重升级召回率；
- 错误承诺率、工具成功率、任务完成率、延迟、Token和成本；
- 至少8类故障注入；
- 所有写操作和外部动作具备人工门禁，公开演示中固定关闭。
