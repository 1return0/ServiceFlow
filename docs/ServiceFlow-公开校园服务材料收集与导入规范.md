# ServiceFlow 公开校园服务材料收集与导入规范

## 1. 目标与边界

本项目使用公开、官方、脱敏的校园 IT 与教学服务材料，构建用于演示的 RAG Corpus。它不收集真实学生账号、密码、身份证件、手机号、内部工单、未公开系统地址或个人联系方式。

真实公开来源与项目内演示材料必须区分：

- `official_campus`：公开学校官网或信息中心页面，且经人工复核来源与适用范围。
- `demonstration`：项目为教学编写的合成材料，不能伪装为真实校规或官方流程。

来源复核清单：`agent-service/data/support-knowledge/public-source-review-v1.json`。

## 2. 一条材料可以进入 Corpus 的最低条件

1. 公开可访问，域名或发布主体能确认是学校官方单位。
2. 内容属于学生能接触的服务：账号、网络、教学系统、教室设备或服务流程。
3. 明确记录 `source_reference`、`source_kind`、`source_review_status`、`source_review_reference` 与 `corpus_version`。
4. 原始 Artifact 与解析后 Article 都生成各自哈希。
5. 不依赖过期的系统菜单、限时公告、收费规则、联系方式或学校专属认证入口。

## 3. 脱敏与摘要规则

允许保留：

- "确认网络自动获取 IP/DNS"、"记录教室和设备故障"、"自助失败转人工核验"等跨学校稳定的服务原则。
- 面向学生的非敏感排障步骤和需要提交的工单信息类别。

不得保留：

- 用户名、密码、Token、二维码、身份证件、照片、手机号、个人邮箱。
- 精确服务电话、具体工作人员、内网地址、未公开后台地址。
- "一定在 X 分钟修复"等服务承诺。
- 已标明旧版系统、旧学期、临时开放期的具体菜单和时间。

导入时使用**短摘要或人工改写**，不复制整篇网页或整份手册；项目回答必须引用来源，但不替代学校当前官方通知。

## 4. 导入前人工复核表

| 检查项 | 通过条件 | 不通过后的动作 |
| --- | --- | --- |
| 发布主体 | 官方学校域名和机构页面 | 不导入，保留为候选线索 |
| 时效性 | 没有旧版本或临时公告依赖 | 标记 `reference_only_not_imported` |
| 脱敏 | 没有账号、密码、证件、个人联系方式 | 删除敏感段落后再复核 |
| 业务适配 | 能映射到既有五类 category | 不强行新增类别 |
| 来源证据 | 复核记录可定位到原 URL 与本地记录 | 不使用 `official_campus` 标记 |

## 5. 当前首批来源状态

| 来源主题 | 处理决定 | 导入形式 |
| --- | --- | --- |
| 统一身份认证帮助 | 可用 | 脱敏后的账号自助/人工核验摘要 |
| 校园网学生指南 | 可用 | 通用网络连接与认证前检查摘要 |
| 多媒体教室故障报修 | 可用 | 设备故障信息收集与人工转交摘要 |
| 2023 版选课指南 | 不导入 | 仅作“过期材料拒绝”示例 |

## 6. 当前项目能力边界

本项目已经保存来源、审核状态、审核证据与哈希，但尚未实现企业级来源爬虫、域名自动信任、网页快照系统或持续时效监测。因此每次真实材料导入前仍需要人工复核，并且前端未来应明确显示“演示材料/公开来源材料”和来源日期。
